# P0 — Android foundations

Source: Saldima spec, Design, iOS plan, and the Voxglass supporter pattern.
Goal: a standalone GnuCash-compatible Android app, TDD, with the same
accounting verification core as iOS and an optional Saldima link.

- [x] A1 Scaffold: Gradle, `:core`, `:sync`, `:app`, AGPL/NOTICE, SPDX, CI
- [x] A2 `Money`, `Guid`, half-up posting, web vectors

## Exit criteria

- [x] `./gradlew test` and `:app:assembleDebug` green on Ubuntu CI.
- [ ] Verification scenarios match Swift/web vectors to the cent.
      (`MoneyTest`/`GuidTest` assert the same half-up/half-even rules as the
      pinned web vectors, but the `scripts/pull-vectors.sh` that `CLAUDE.md`
      and `docs/vectors.md` call for doesn't exist yet, so nothing actually
      pulls and replays the pinned `money.json`/`guid.json`/`accounts.json`
      — add that before checking this off.)
- [x] Standalone create/open/save `.gnucash` works with zero network.
- [ ] Optional sync round-trips a book and can be removed without data loss.
      (blocked on A7 above.)
- [ ] Supporter purchase success/cancel/pending tested with fakes; no gating.
      (`TemplatesSupporterTest` covers `Purchased` and `Cancelled` with fakes;
      `SupporterPurchaseResult.Pending` is modelled but has no test yet.)
- [ ] Owner installs the app on a physical Android device and records QA.

## Human-only

Play Console app/record, `saldima_supporter` product, signing key, Play
environment, device QA. No uploads or releases by agents.

## Risks and open questions

- **XML-canonical migration landed (A4 superseded).**
  `docs/architecture/TECHNICAL-DESIGN.md`'s Phase 1-2 is done:
  `BookRepository` is now backed by `XmlBookDocument` (parse once, mutate
  in memory, atomically rewrite on save, the same way desktop GnuCash's own
  XML backend behaves) — read, create/update/delete account, and post all
  go through it. `SqliteBookReader` stays as the import-only path for a
  legacy SQLite-dialect file (materialized into a fresh XML working copy
  via `XmlBookDocument.build`); `SqliteBookWriter` remains as groundwork for
  a future "export as SQLite" feature but is no longer on the live path.
  Mirrors the same decision in the web and iOS repos. Zero-knowledge sync
  (A7) stays deferred regardless.
- **StAX on-device runtime, unverified.** `XmlBookDocument`'s parser is
  built on `javax.xml.stream` (already used by the pre-existing
  `XmlBookReader`), which compiles against the Android SDK and runs in
  `:core`'s JVM unit tests, including the ~3,300-transaction Gronewald
  fixture. It has not been exercised on a physical device or emulator in
  this sandbox (no device/emulator available); the iOS track hit a real
  platform gap this same kind of assumption would have missed
  (`XMLDocument`/`XMLElement` compiled on Linux but do not exist on iOS at
  all), so flagging this rather than asserting it is proven. Confirm with a
  real import/create/post/save pass on the owner's device before treating
  this as fully verified.
