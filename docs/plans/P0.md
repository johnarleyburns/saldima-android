# P0 — Android foundations

Source: Saldima spec, Design, iOS plan, and the Voxglass supporter pattern.
Goal: a standalone GnuCash-compatible Android app, TDD, with the same
accounting verification core as iOS and an optional Saldima link.

## Checklist

- [ ] A0 Agent handoff: CLAUDE.md, plan and issues
- [ ] A1 Scaffold: Gradle, `:core`, `:sync`, `:app`, AGPL/NOTICE, SPDX, CI
- [ ] A2 `Money`, `Guid`, half-up posting, web vectors
- [ ] A3 Ledger/report verification kernel + GnuCash scenarios
- [ ] A4 Standalone SQLite book, templates and account tree CRUD
      (JVM: format detection + XML reader landed in #16; SQLite writes still open)
- [ ] A5 Compose shell: Accounts, Register, Receipts, Reports, Settings
- [ ] A6 Supporter one-time consumable via Play Billing (never gates)
- [ ] A7 Optional `/api/v1` sync/upload/download/merge
- [ ] A8 Exit gate: owner device QA and parity with iOS core

## Exit criteria

- [ ] `./gradlew test` and `:app:assembleDebug` green on Ubuntu CI.
- [ ] Verification scenarios match Swift/web vectors to the cent.
- [ ] Standalone create/open/save `.gnucash` works with zero network.
- [ ] Optional sync round-trips a book and can be removed without data loss.
- [ ] Supporter purchase success/cancel/pending tested with fakes; no gating.
- [ ] Owner installs the app on a physical Android device and records QA.

## Human-only

Play Console app/record, `saldima_supporter` product, signing key, Play
environment, device QA. No uploads or releases by agents.
